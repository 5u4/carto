Carto 链接指向的是节点，而不是某次构建产出的页面路径。解析时再把这个稳定的逻辑名称与节点的父链、当前语言环境以及联邦文档集前缀组合，得到最终 URL。本页只讨论这一步地址决策：节点从磁盘进入内存的过程见[文档模型](carto:document-model)，命令如何组织校验与报错见 [CLI 工作流](carto:cli-workflow)，构建时如何改写作者写下的链接见[渲染流水线](carto:rendering-pipeline)。

## 父链如何形成多语言路径

`rootChain` 从目标 id 出发，按 `parent` 逐级查找，并把每个找到的节点插到数组开头，因此结果顺序始终是根到叶。遇到根节点、找不到的父节点或已经访问过的 id 时停止。随后 `urlPath` 拼接这些 id，加上可选的文档集前缀；当前语言等于站点默认语言时不加语言段，否则在开头加 `/<locale>`；结果一律以 `/` 结尾。`packages/core/src/tree.ts:13-29`

以本页为例，它的父节点是 `overview`。同一个逻辑 id 会因部署上下文而得到不同的物理地址：

| 上下文 | URL 形态 |
| --- | --- |
| 本地文档集、站点默认语言 | `/overview/navigation-federation/` |
| 本地文档集、非默认语言 `zh` | `/zh/overview/navigation-federation/` |
| 联邦根文档集、站点默认语言 | `/self/overview/navigation-federation/` |
| 外部文档集、非默认语言 `zh`、前缀为 `/core-a1b2c3d4` | `/zh/core-a1b2c3d4/overview/navigation-federation/` |

进入联邦模式后，是否省略语言段以整个站点的默认语言为准，而不是让每个文档集各自隐藏自己的默认语言。解析器把站点级默认语言传给 `urlPath`，因而所有文档集遵守同一条规则。`packages/core/src/resolver.ts:52-61` `packages/core/src/resolver.ts:76-79`

父子关系的完整性由另一段逻辑检查。父节点不存在时产生 `dangling-parent` 警告，便于仍在组装中的局部树继续被检查；当前祖先路径里再次出现同一 id，则产生去重后的 `parent-cycle` 错误。`packages/core/src/tree.ts:32-67`

:::caution[祖先链就是 URL 的一部分]
修改节点的 `parent` 可能会改变解析出的祖先链，进而改变该节点及其后代的 URL，即使它们的 `carto:` 逻辑 id 完全没变。若只是把一个无法解析的父 id 换成另一个同样无法解析的父 id，解析出的链不变，URL 也不会变。悬空父节点还会让路径链停在最后一个能找到的节点，因此这项警告直接关系到导航结果，并非无关紧要的元数据提示。
:::

## 联邦如何确定文档集身份

文件型联邦以“目标文档集真实路径相对于最外层联邦根目录的路径”作为身份输入。Carto 先统一路径分隔符，再对带 `file:` 前缀的字符串计算 SHA-256，并取前八位十六进制字符。由于计算前会解析真实路径，经不同别名到达同一目录时仍会汇合到同一个图身份。`packages/core/src/graph.ts:28-35`

图加载从根 manifest 开始，递归跟随每个文档集声明的联邦条目。文件条目相对于声明它的文档根目录解析；`git` 条目会立即失败，因为 git 联邦尚未实现。每个文档集自己的 `aliasToHash` 记录“本集所写的别名如何到达另一身份”，全图共享的 `byHash` 则保证多个别名指向同一物理文档集时只加载一次。加载文件条目时遇到的非联邦错误会包装成 `FederationError`，并保留发起声明的别名和解析后的路径；已经是 `FederationError` 的错误则原样继续抛出。`packages/core/src/graph.ts:37-73`

前缀负责把共站部署的各文档集隔离到不同 URL 空间。根文档集只要声明了联邦，前缀就是 `/self`；没有联邦时仍为空。非根文档集统一采用 `/<字典序最小的别名>-<身份哈希>`。所以多个别名可以解析到同一文档集，却不会产生多套规范 URL 前缀。`packages/core/src/graph.ts:75-88`

## 从逻辑链接到 URL 的解析流程

```text
Markdown 目标
    |
    v
识别 `carto:`，按第一个 `#` 拆出片段
    |
    +-- 没有 `/` ------------ 本地 id
    |                            |
    |                            +-- 校验 id -> 在当前节点表查找
    |                            +-- 父链 -> 语言段 + 本集前缀
    |
    +-- 第一个 `/` ----------- 联邦别名 + 目标 id
                                 |
                                 +-- 要求联邦上下文
                                 +-- 校验别名和 id
                                 +-- aliasToHash -> byHash -> 目标节点
                                 +-- 父链 -> 语言段 + 目标集前缀
    |
    v
片段非空时追加 `#anchor`；空的 `#` 标记省略 -> { ok: true, url, id }
```

语法解析只接收 `carto:` scheme，先按第一个 `#` 分离片段，再把第一个 `/` 当作联邦边界。没有斜杠就是本地链接；有斜杠则解析为 `{ alias, id }`。`packages/core/src/resolver.ts:10-25`

本地分支校验 id 后在当前 manifest 中查找节点，再调用 `urlPath`。联邦分支还要求存在联邦上下文，并依次校验别名与 id、通过 `aliasToHash` 找到 `byHash` 中的文档集、在目标集内查节点，最后带着该文档集的前缀调用 `urlPath`。两条成功路径都只会原样追加非空片段，并随 URL 返回解析到的节点 id；空片段标记会被省略。`packages/core/src/resolver.ts:52-79`

## 失败也是稳定的类型结果

逻辑链接无效时，解析函数返回可辨识联合结果，而不是抛出异常。调用方因此能保留具体失败原因，不必把所有情况都压成一个“未找到”。错误类型与成功/失败结果契约集中定义在一起。`packages/core/src/resolver.ts:27-50`

| 错误类型 | 失败边界 |
| --- | --- |
| `not-a-carto-link` | 目标不是以 `carto:` 开头。 |
| `malformed` | 本地 id、联邦别名或联邦 id 不符合 id 格式。 |
| `federation-unsupported` | 链接写成 `alias/id`，但调用方没有提供联邦上下文。 |
| `unknown-alias` | 当前文档集没有该别名映射，或映射到的身份不在已加载图中。 |
| `unknown-id` | id 格式有效，但当前 manifest 中不存在该本地节点。 |
| `unknown-federated-id` | 别名已经到达已加载的目标集，但目标集内没有所需 id。 |

这些失败分支的先后次序是明确的：联邦链接先检查是否支持联邦，再检查语法；语法通过后才查别名，别名通过后才查目标节点。`packages/core/src/resolver.ts:52-77`

## 修改时应落在哪一层

- 祖先链、语言段位置或末尾斜杠规则应改 `tree.ts`，同时保证树检查的严重级别与遍历行为一致。
- 文件系统联邦身份、图去重、支持的联邦条目类型或规范前缀应改 `graph.ts`。
- 逻辑链接语法、查找顺序或公开的失败分类应改 `resolver.ts`；使用方会按这些可辨识的错误类型处理结果。

manifest 的读写不属于本层；解析器也不决定 Markdown 如何被改写，更不负责把错误以何种文案展示给用户。这样的边界让校验与渲染都能复用地址计算，而无需接管导航模型本身。
