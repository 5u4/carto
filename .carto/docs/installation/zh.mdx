Carto 不是通过全局包仓库安装的，而是由安装器维护一份源码检出，再从中发布两个稳定的符号链接：一个提供命令，另一个提供编码代理技能。排查更新问题时应先分清这两层：拉取和构建发生在源码检出中，终端能否使用 Carto 则取决于符号链接和 PATH 配置。若要先了解仓库各包的分工，请看[仓库概览](carto:overview)；安装后的技能如何指导代理，请看[编写工作流](carto:authoring-workflow)；可执行文件背后的命令行为，请看 [CLI 工作流](carto:cli-workflow)。

## 前置条件与目录归属

这条安装路径需要 Bash、Git、curl、Node 22.12 或更高版本，以及 Corepack 或 pnpm 10。文档中的单行命令只用 curl 传入脚本；脚本本身会检查 Git 和 Node、校验 Node 最低版本，并优先使用 `corepack pnpm`，没有 Corepack 时则拒绝低于 10 的 pnpm。README.md:11-16 install.sh:40-60 install.sh:278-283

安装根目录默认为 `~/.carto`，也可通过 `CARTO_DIR` 修改；相对路径会基于当前工作目录解析。`CARTO_REPO_URL` 可改用其他上游地址，但命令和技能的接入位置始终位于用户主目录下。所有权标记用于识别安装器管理的根目录；三个 PATH 状态文件只记录安装器自动修改 shell 文件的状态，未发生修改时不会存在。install.sh:4-23 install.sh:74-96 install.sh:195-223

安装器接管目录前，会拒绝符号链接或非目录形式的安装根目录。对于尚无所有权标记的非空目录，只有其中唯一内容恰好是预期的 `repo` 检出且该检出通过校验时才会继续；其他情况必须另选 `CARTO_DIR`。确认后，安装器写入 `carto-installer-v1` 标记。install.sh:74-96

## 安装与更新事务

```text
检查依赖和链接冲突
          │
          ▼
接管安装根目录 ──► 克隆 main / 快进已有 main
          │
          ▼
按锁文件安装依赖 ──► 构建全部工作区 ──► 确认 CLI 产物
          │
          ▼
创建缺失的命令和技能链接 ──► 配置 PATH ──► 报告成功
```

这个顺序界定了事务在实践中的边界：安装器会先检查链接冲突，再接管或推进源码检出；检出完成克隆或更新并成功构建后，才会对外暴露新命令或技能链接；PATH 接入是最后一步。install.sh:278-294

### 只克隆或快进，不覆盖本地工作

首次运行时，安装器只浅克隆 `main` 这一分支。更新已有检出时，远端地址必须与配置完全一致，当前分支必须是 `main`，且不能有已跟踪的改动或未被忽略的未跟踪文件。拉取 `origin/main` 后，当前 `HEAD` 还必须是其祖先，随后才执行仅快进合并。遇到本地提交、分叉历史、游离 HEAD 或该工作区检查所报告的改动时，安装器会拒绝继续，而不会强制重置；被忽略的文件不会出现在检查结果中。install.sh:63-72 install.sh:98-110

依赖安装严格使用仓库锁文件，随后构建所有工作区。只有 `packages/cli/dist/index.js` 确实生成后才会进入发布阶段，并且链接处理前会先为该产物添加可执行权限。install.sh:113-118

因此，重新执行文档中的安装命令，实际含义是“校验、快进、重新构建”，而不是“替换整个目录”。README 也明确让安装和更新共用同一条命令。README.md:17-33

### 通过稳定链接发布

安装器会先确认每个目标位置要么不存在，要么已经是它所拥有、且指向完全相同目标的符号链接。目标处若是普通文件或其他符号链接，安装器绝不会覆盖。构建完成后也只创建缺失链接，所以更新时会保留已有的合规链接，由其继续指向检出中的新内容，而不会用临时链接做替换。install.sh:120-157

默认安装布局如下：

| 用途 | 文件系统位置 |
|---|---|
| 安装器管理的源码检出 | `~/.carto/repo` |
| 构建后的 CLI 目标 | `~/.carto/repo/packages/cli/dist/index.js` |
| 用户命令 | `~/.local/bin/carto` → CLI 目标 |
| 技能目标 | `~/.carto/repo/skills/carto` |
| 代理可见的技能 | `~/.agents/skills/carto` → 技能目标 |
| 所有权标记 | `~/.carto/.installer-owner` |
| PATH 状态（仅自动修改 shell 文件后存在） | `~/.carto/.path-rc`、`.path-rc.before`、`.path-rc.after` |

安装器接管根目录后，所有权标记就会存在。三个 PATH 状态文件仅在安装器自动追加 PATH 配置时创建；若 PATH 已配置、shell 不受支持，或目标文件已有完全相同的导出语句，提前返回时不会创建这些文件。install.sh:74-96 install.sh:195-223

这些位置分别定义，因此修改 `CARTO_DIR` 只会移动检出和链接目标，不会移动 `~/.local/bin` 或 `~/.agents/skills`。install.sh:11-22 README 同样列出了默认检出、CLI 链接、技能链接以及安装后的 `carto --help` 检查。README.md:25-33

## 接入 PATH

若 `~/.local/bin` 已在 `PATH` 中，安装器不会改动任何 shell 文件。否则，zsh 使用 `~/.zprofile`；bash 优先选择已有的 `~/.bash_profile` 或 `~/.bash_login`，都没有时使用 `~/.profile`。安装器不会重复添加完全相同的导出语句；它会保存修改前后的文件快照、记住所改文件，并追加 `export PATH="$HOME/.local/bin:$PATH"`。无法自动处理的 shell 只会收到手动配置提示，不会被擅自修改。install.sh:160-225

登录配置文件的改动不会影响当前进程，因此应打开新 shell，再用 `carto --help` 验证安装。README.md:28-33

## 失败边界与清理

`set -euo pipefail` 会在首个未处理错误处终止运行，但脚本没有自动回滚的 trap。首次安装时，克隆和构建先于链接与 PATH 修改，因此构建失败不会发布新命令或技能；不过所有权标记和源码检出可能会留下，供状态干净时重新执行。更新已有安装时，快进发生在构建之前，原有链接又会继续指向该检出。因此，这套更新会防止所有权冲突和本地工作被覆盖，却不是能同时回滚检出与构建的原子事务：构建失败可能留下已推进的检出，修复或重跑成功前不应依赖其中的命令。install.sh:1-2 install.sh:98-118 install.sh:278-294

显式卸载才是对应的清理事务。只有当符号链接仍指向安装器预期的准确目标时，它才会删除该链接。处理 PATH 时，如果 shell 文件与安装完成时的快照逐字节相同，就恢复原始快照；如果用户后来编辑过文件，则移除最后一条完全匹配的 PATH 配置，同时保留其他改动。install.sh:227-275

最后，只有安装根目录中存在内容正确且不是符号链接的所有权标记时，卸载才会删除整个根目录；否则会保留目录并说明原因。`--uninstall`/`uninstall` 模式覆盖安装器拥有的 CLI 链接、技能链接、PATH 配置和源码检出。install.sh:297-331

## 贡献者检出与用户安装分离

贡献者可以在任意源码检出中安装依赖、构建工作区，再直接执行 `node packages/cli/dist/index.js --help`。这一流程刻意不创建 pnpm 全局链接；用户终端中的 `carto` 命令仍统一交由 `install.sh` 管理。README.md:83-94
