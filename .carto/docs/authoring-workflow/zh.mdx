一次 Carto 编写任务从开发者给出的范围开始。编码代理负责理解与写作；CLI 负责哈希、结构校验、链接和新鲜度。两次彼此独立、全新的只读审阅分别检查正确性与展示质量，通过后 CLI 才能为结果盖章。`skills/carto/SKILL.md:17-20` `skills/carto/SKILL.md:50-60` `skills/carto/SKILL.md:92-110`

## 先锁定范围

选择分支前，先探测已安装 CLI 并确认 `carto.json` 存在。状态或覆盖率检查可以直接报告；新建与刷新必须有明确范围。`skills/carto/SKILL.md:22-55`

```text
请求
├─ 检查状态 / 覆盖率
│  └─ 运行指定命令；报告结果
└─ 新建 / 刷新明确范围
   ├─ status + coverage → 与请求范围取交集
   ├─ 交集为空 → 不改写，直接结束
   ├─ 普通编写 → 继续
   └─ 删除、改名、调整父级、大规模重分配、仍有歧义
      └─ 列出准确受影响 bundle；等待批准
```

## 规划一个答案和它的 view spine

每个节点只回答一个长期有效的开发者问题。先从一项端到端职责或流程出发；只有相邻问题在所有者、入口、契约、流程、不变量或改动面上有实质差异，而且值得独立导航或独立判定新鲜度时，才拆成另一个节点。`skills/carto/references/documenting.md:7-32`

起草前，检查实现、调用方、副作用、共享契约与可观察行为。先制定一份语言无关的证据计划，用 coverage map 明确每个子问题：

```text
核心开发者问题
├─ 支撑子问题
│  ├─ 读者应得到的结论
│  ├─ 最小且经核验的 view ── 或 ── 可靠的纯 prose 理由
│  └─ 精确的可执行证据
├─ 只用于导航的相邻 carto: 目标
└─ sources = 任何变化后可能推翻答案的文件
```

`skills/carto/references/documenting.md:34-95` `skills/carto/references/presenting-code.md:9-55`

view spine 承载顺序、分支、状态、关系、契约对比、改动面和复现行为。prose 负责定向与解释影响，不再复述同一个形状。每种语言保留相同的 view 用途、事实、链接和精确锚点，同时使用本地技术读者自然的表达。`skills/carto/references/presenting-code.md:11-37` `skills/carto/references/presenting-code.md:147-160` `skills/carto/references/documenting.md:97-127`

## Sync 前通过两次审计

```text
按共享计划编写全部语言
  ↓
全新的正确性审阅
  ├─ 默认语言页面 + node.json + 可执行来源
  └─ 来源、锚点、关系、事实、流程、示例
  ↓ 在所有语言中修正已接受的事实发现
另一轮全新的展示审阅
  ├─ 所有语言 + 证据计划 + coverage map
  └─ 缺失形状、重复/装饰 view、分布、语言间用途
  ↓ 在所有语言中修正已接受的展示发现
carto sync <id...>
  ↓
carto validate
  ↓
carto status → 本次触及的每个 id 都是 fresh
```

正确性审阅不检查文风；它只返回有证据的事实发现，不编辑也不同步。`skills/carto/references/auditing.md:3-47` 正确性通过后，再进行一轮独立、全新的只读展示审阅，不重新打开源码，也不复核事实。可委派时由另一名审阅者执行；无法委派时，父代理另起一次明确分隔的审阅。`skills/carto/SKILL.md:92-110` `skills/carto/references/auditing-presentation.md:3-41`

父代理必须在定向同步前，把每条已接受发现应用到所有语言。范围外节点即使陈旧，校验仍可能通过，因此最后还要用状态检查确认本次触及的每个 id 都回到 `fresh`。`skills/carto/SKILL.md:92-132`

## 职责边界

| 参与者 | 负责 | 不可替代 |
| --- | --- | --- |
| 请求者 | 定义范围；批准有歧义或会破坏既有结构的改动。 | 证据选择或 CLI 结果。 |
| 编码代理 | 调查可执行路径，设计问题与 coverage map，推导 `sources`，编写全部语言，并处理审计发现。 | 哈希、链接解析或新鲜度计算。 |
| 正确性审阅者 | 用可执行证据检查完整的范围内默认语言页面。 | 编辑、同步、展示审查或其他语言审查。 |
| 展示审阅者 | 检查 view-spine 覆盖与所有语言之间的用途一致性。 | 事实修正、源码复核、编辑或同步。 |
| Carto CLI | 报告状态与覆盖率，为已审阅 id 盖章，校验文档图并报告最终新鲜度。 | 决定页面应教什么，或判断证据与展示是否充分。 |

这些角色边界来自生成循环和两份审计契约。`skills/carto/SKILL.md:50-132` `skills/carto/references/auditing.md:6-47` `skills/carto/references/auditing-presentation.md:6-70`

来源拆分、职责迁移、入口或契约变化导致计划失效时，应先修改 coverage map、sources 与全部语言，再执行同步。删除陈旧来源并不能刷新答案。`skills/carto/SKILL.md:141-152` `skills/carto/references/documenting.md:79-127`
