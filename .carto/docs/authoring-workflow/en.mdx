A Carto authoring run starts from a developer's scope. The coding agent owns interpretation and authoring; the CLI owns hashing, structural validation, links, and freshness. Two distinct fresh read-only passes check correctness and presentation before the CLI may stamp the result. `skills/carto/SKILL.md:17-20` `skills/carto/SKILL.md:50-60` `skills/carto/SKILL.md:92-110`

## Checkpoint the scope

Probe the installed CLI and require `carto.json` before choosing a branch. Inspection can report status or coverage directly; creation and refresh require a stated scope. `skills/carto/SKILL.md:22-55`

```text
request
├─ inspect status / coverage
│  └─ run the requested command; report
└─ create / refresh a named scope
   ├─ status + coverage → intersect facts with scope
   ├─ empty intersection → stop without rewriting
   ├─ ordinary authoring → continue
   └─ deletion, rename, reparenting, large reassignment, ambiguity
      └─ list exact affected bundles; wait for approval
```

## Plan one answer and its view spine

Each node answers one durable developer question. Start with one end-to-end responsibility or flow, and split only for a neighboring question with a meaningfully distinct owner, entry point, contract, flow, invariant, or change surface that benefits from independent navigation or freshness. `skills/carto/references/documenting.md:7-32`

Before drafting, inspect the implementation, callers, effects, shared contracts, and observable behavior. Build one locale-neutral evidence plan whose coverage map makes every supporting subquestion explicit:

```text
primary developer question
├─ supporting subquestion
│  ├─ reader takeaway
│  ├─ smallest verified view ── or ── sound prose-only reason
│  └─ exact executable evidence
├─ neighboring carto: targets for navigation
└─ sources = every file whose change could invalidate the answer
```

`skills/carto/references/documenting.md:34-95` `skills/carto/references/presenting-code.md:9-55`

The view spine carries sequence, branch, state, relationship, contract comparison, change surface, and reproduced behavior. Prose orients the reader and explains implications instead of narrating the same shape. Every locale preserves the mapped view purposes, facts, links, and exact anchors while using native technical language. `skills/carto/references/presenting-code.md:11-37` `skills/carto/references/presenting-code.md:147-160` `skills/carto/references/documenting.md:97-127`

## Pass two audits before sync

```text
author every locale from the shared plan
  ↓
fresh correctness pass
  ├─ default-locale pages + node.json + executable sources
  └─ sources, anchors, relationships, claims, flows, examples
  ↓ fix accepted factual findings in every locale
separate fresh presentation pass
  ├─ every locale + evidence plan + coverage map
  └─ missing shapes, duplicate/decorative views, distribution, locale purpose
  ↓ fix accepted presentation findings in every locale
carto sync <id...>
  ↓
carto validate
  ↓
carto status → every touched id is fresh
```

The correctness pass never becomes a style review. It returns evidence-backed factual findings without editing or syncing. `skills/carto/references/auditing.md:3-47` After correctness is clean, a separate fresh read-only presentation pass checks the mapped views without reopening source code or re-auditing facts. Delegated runs use a different reviewer; without delegation, the parent performs a new distinct pass. `skills/carto/SKILL.md:92-110` `skills/carto/references/auditing-presentation.md:3-41`

The parent resolves every accepted finding in all locales before targeted sync. Validation may remain green while unrelated nodes are stale, so final status must still show every touched id as `fresh`. `skills/carto/SKILL.md:92-132`

## Responsibility boundary

| Participant | Owns | Does not replace |
| --- | --- | --- |
| Requester | Defines scope; approves ambiguous or structurally destructive changes. | Evidence selection or CLI results. |
| Coding agent | Investigates executable paths, designs the question and coverage map, derives `sources`, authors every locale, and resolves findings. | Hashing, link resolution, or freshness calculation. |
| Correctness reviewer | Checks the complete in-scope default-locale set against executable evidence. | Editing, syncing, presentation review, or locale review. |
| Presentation reviewer | Checks view-spine coverage and purpose parity across every locale. | Factual corrections, source review, editing, or syncing. |
| Carto CLI | Reports status and coverage, stamps reviewed ids, validates the document graph, and reports final freshness. | Deciding what a page should teach or whether its evidence and presentation are sufficient. |

These role boundaries come from the generation loop and the two audit contracts. `skills/carto/SKILL.md:50-132` `skills/carto/references/auditing.md:6-47` `skills/carto/references/auditing-presentation.md:6-70`

When a source split, responsibility move, entry-point change, or contract change invalidates the plan, revise the coverage map, sources, and every locale before syncing. Dropping a stale source does not refresh an answer. `skills/carto/SKILL.md:141-152` `skills/carto/references/documenting.md:79-127`
